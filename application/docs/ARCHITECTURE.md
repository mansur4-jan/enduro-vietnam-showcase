# Действующая архитектура

Текущее приложение — Next.js 16.3.8 App Router, React 19.2.3, TypeScript и PostgreSQL. Точные зависимости закреплены в package-lock.json. Локальная среда проверки: Node.js 24.1.0, npm 11.3.0. Все S02–S14 разрешены пользователем к автономной работе; отсутствие внешних подключений не считается успешным выпуском.

## Источники и владельцы данных

- `.shipstudio/source`, исходные ZIP и `content/pages.json` — неизменяемые свидетельства публичного сайта.
- `content/exported-pages` — 53 отдельных редакторских экспорта; `content/link-ledger.json/csv` сохраняют 5 602 исходных вхождения ссылок.
- `data/catalog-seed.json` — воспроизводимый импорт публичного архива и предоставленного ТЗ: 17 туров и 52 позиции аренды после сверки предоставленного XLSX, включая RU-only Honda Winner X.
- PostgreSQL — текущие черновики, опубликованные снимки, ревизии, цены, переводы, категории, URL, организации, заявки и очередь.
- `data/source-audit.json` — исходные замечания XLSX. `data/audit-register.json` — текущий статус всех 91 EV и 18 T замечаний; CSV генерируется из него.
- `.shipstudio/migration.json` — единственный текущий отчёт о ходе миграции. Проверяемые результаты находятся в указанных в нём JSON-отчётах.

Изменённые редактором записи не перезаписываются импортом. Неизвестные суммы остаются NULL. USD хранится в центах, VND — в донгах. Тарифы аренды и залог независимы. RU и EN используют один объект коммерческих данных; неподтверждённые варианты, условия и цены находятся в conflicts.

## База и права

Локально используется PGlite с постоянным каталогом `.data/postgres`. Только один процесс `server/database-service.mjs` открывает его; Next.js и CLI обращаются к мосту на 127.0.0.1:54329 с приватным ключом `.data/bridge-key`. PGlite не заявлен как production-сервер.

При DATABASE_URL используется обычный PostgreSQL через pg. SQL-миграции находятся в `db/migrations`; применяются последовательно. В пользовательской транзакции устанавливаются app.user_id и роль enduro_app. RLS и триггеры ограничивают организацию, публикацию, изменение опубликованных данных и владение URL.

Роли: owner — полный доступ; staff — явные permissions; partner — собственная организация, черновики и отправка на проверку. Партнёр не публикует и не читает заявки. Staff без общего leads видит только назначенные ему заявки и меняет только статус. Назначение снимает/выдаёт owner или staff с leads. Пользовательская роль не имеет доступа к хешам паролей и сессионным таблицам.

Вход по приглашению, пароли scrypt, 12-часовые HttpOnly/SameSite Strict сессии, отзыв доступа на следующем запросе, одноразовое восстановление, TOTP для владельца. MFA реализована и проверена на временной учётной записи; реальному владельцу требуется привязать своё устройство до выпуска.

## Вывод и редактор

`app/page.tsx` и catch-all читают опубликованные снимки. Общие компоненты находятся в `components/catalog`. Сохранены старые адреса; новые карточки аренды, направления, категории и поставщик используют общие шаблоны. URL старой публикации превращается в точный редирект только при утверждении новой версии.

`/admin` редактирует переводы, программы, характеристики, тарифы, варианты и медиа. Ревизии и optimistic version защищают от потери чужой правки. До одобрения публичная версия остаётся прежней. `/admin/preview/{id}` показывает полный черновой шаблон под авторизацией без отправки заявки. `/admin/imports` показывает карантин, конфликты и историю импорта.

Фото: public/assets — исходные локальные файлы; новые загрузки — `.data/media`. Sharp проверяет содержимое JPEG/PNG/WebP, ограничивает размер/пиксели, нормализует в WebP до 2000 px и удаляет метаданные. Неопубликованное фото доступно только разрешённому редактору. Fixture-записи исключены из публичных выборок, sitemap и выдачи медиа.

## Заявки и доставка

UI → `/api/leads` → транзакция PostgreSQL: заявка, снимок цены/условий, событие lead_saved и два outbox задания. Успех возвращается после commit. UUID idempotency-key защищает сетевые повторы; цена берётся сервером. Есть проверка Origin, даты, согласия, honeypot и ограничение частоты.

`server/outbox-worker.mjs` — отдельный долговечный обработчик. Блокировка строк/lease, повтор с задержкой, независимые email и Telegram. Без DELIVERY_ENABLED=1 и полного набора параметров задача остаётся blocked. Resend/Telegram успех требует ответа с идентификатором сообщения. Проверены только mock-транспорты, реальная доставка не подтверждена. Внешняя доставка допускает повтор при потере ответа провайдера; exactly-once для Telegram не обещается.

В dev launcher принудительно устанавливает DELIVERY_ENABLED=0. Старый `/api/booking` остаётся отключённым endpoint исторического экспорта, новые формы используют `/api/leads`. Данные посетителя не отправляются в стороннюю аналитику; lead_saved — локальное событие без контактов.

## Дизайн и проверка

Пользователь отложил исходное визуальное совпадение и разрешил реализацию ТЗ. Новый каталог использует локальный Inter, контейнер 1200 px, фон #f7f7f3, текст #202620, акцент #c7f265 и радиус 18 px. Исходные вычисленные токены сохранены в content/design-system.json как архив; это не токены нового каталога. /style-guide показывает действующий интерфейс.

SSR metadata блокирует ранний поток для корректного HTTP 404. Не добавлять общий loading.tsx без проверки статуса неизвестных карточек. Canonical и hreflang указывают на реально существующие переводы. Фильтры noindex; пустая аренда авто noindex; кабинет всегда noindex и private/no-store. Local-safe/dev закрыты от индексации.

## Эксплуатационные границы

Dockerfile/compose.yaml подготовлены для PostgreSQL, web и отдельного worker; Docker и удалённое развёртывание здесь не проверены. Production требует HTTPS reverse proxy, приватное окружение, независимый backup и проверку реальных каналов. Локальный зашифрованный snapshot восстановлен в отдельную PGlite; это не доказательство offsite хранения или remote PostgreSQL восстановления.
